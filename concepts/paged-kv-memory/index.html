    分页式 KV 管理🔗

    一句话定义：把 KV Cache 切成定长的 block，用一张 block table 把请求视角的连续「逻辑块」映射到显存中不连续的「物理块」——即操作系统虚拟内存分页在 LLM 推理上的直接复用。

    为什么需要它🔗

    深度学习框架的算子普遍要求张量物理连续。而 KV Cache 有两个与训练张量不同的性质：

    • 它随生成动态增长；
    • 它的最终长度事先不可知。

    「连续存储 + 长度未知」只剩一个做法：按最大可能长度预分配。由此产生三类浪费：

    类型 成因 何时可知 性质
    Reserved（预留） 为未来 token 占住的槽位 请求开始时 最终会被用到，但整个生命周期占着空间
    内部碎片 按最大长度过量分配 请求结束后 纯浪费
    外部碎片 分配器（如 buddy）留下的空隙 请求开始前 纯浪费

    实测中，这三者合起来可以吃掉 60%–80% 的 KV 显存。而 KV 显存直接决定并发批量，并发批量决定吞吐——浪费显存等于浪费吞吐。

    它是怎么工作的🔗

    三层结构🔗

    • 逻辑 KV 块：请求视角的连续块序列，从左往右填充。最后一块的空位留给后续生成。
    • 物理 KV 块：预先分配一大片连续显存，切成等大的物理块。
    • Block table：每个请求一张，记录「逻辑块 → 物理块编号」以及每块已填充的位置数。

    只有前面的块全满时才分配新块，因此每个请求的显存浪费被限制在一个块以内。

    与操作系统的对应🔗

    操作系统 分页式 KV 管理
    page KV block
    byte token
    process request
    page table block table
    demand paging 按需分配物理块
    copy-on-write（fork） 块级 CoW + 引用计数
    swap to disk swap 到 CPU 内存
    共享库 共享 prefix 的物理块

    共享与写时复制🔗

    多个序列的逻辑块可以指向同一个物理块，每个物理块维护引用计数。当某个序列需要写入引用计数大于 1 的块时：分配新物理块 → 拷贝内容 → 原块引用计数减 1。引用计数归零的块被回收。

    典型的共享场景：

    • parallel sampling：多个采样序列共享整段 prompt 的块。
    • beam search：共享 prompt 与生成过程中的公共前缀，共享结构随解码动态变化（类似 OS 中由复合 fork 形成的进程树）。
    • shared prefix：system prompt、few-shot 示例等跨请求共享的前缀。

    块大小的取舍🔗

    增大 block size 效果
    GPU 并行度 变好（kernel 一次处理更多位置）
    内部碎片 变差（每请求最多浪费一块）
    共享概率 变差（共享要求整块相同）
    换出效率 变好（大块传输能压满 PCIe 带宽）

    实践中 16 是对负载分布最不敏感的取值：足够大以利用 GPU 并行度，足够小以避免短序列上的显著内部碎片。

    抢占与恢复🔗

    显存不足时需要淘汰某些序列。由于一个序列的所有块总是一起被访问，采用 all-or-nothing 淘汰——整个序列要么全留要么全走。这一点消掉了 OS 中最难的部分：不需要页面置换的预测启发式。

    恢复有两条路：

    方式 成本结构 何时更优
    Swap（换出到 CPU 内存） 数据量 / 有效 PCIe 带宽；小块传输压不满带宽 block size 大时
    Recompute（重算） 已生成 token 与原 prompt 拼成新 prompt，一次 prefill 并行算完；与 block size 无关 block size 小时

    重算这条路在 OS 里不存在——页的内容是任意数据，无法重新计算；而 KV 是 prompt 的确定性函数。

    关键性质与代价🔗

    收益 代价
    显存浪费限制在一个块以内 每次访存多一次 block table 间接寻址
    块级共享 + CoW，支持复杂解码算法 需要自定义 attention kernel（框架算子要求连续张量）
    统一映射层对 kernel 隐藏共享结构，扩大可批处理集合 注意力 kernel 相对连续实现有可观测的额外延迟
    数学结果逐位不变 抢占机制引入长尾延迟

    适用条件（两条必须同时满足）：

    1. 内存分配是动态的（分配量事先不可知）；
    2. 性能受显存容量约束（memory-bound）。

    任一条不满足，间接寻址与非连续访问就是净成本。反例：DNN 训练（张量形状静态）、非 LLM 的 DNN 推理（compute-bound）、以及显存充裕且序列很短的 LLM 配置。

    常见误解🔗

    • 误解：PagedAttention 改变了注意力的数学 → 实际：只是把对 key 的求和按块分组，输出逐位相同，模型精度完全不变。
    • 误解：分页一定更快 → 实际：注意力 kernel 因间接寻址反而更慢；净收益来自并发批量的提升。如果系统不是 memory-bound，净效果是负的。
    • 误解：块越小越省显存 → 实际：块越小内部碎片越少，但 GPU 并行度下降、swap 效率变差。存在最优区间。
    • 误解：共享靠内容比较实现 → 实际：靠引用计数与显式的映射关系。共享结构由解码算法或调用方声明，不是自动内容去重。
